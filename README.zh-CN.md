# NekoBeat

[English](README.md) | [简体中文](README.zh-CN.md)

NekoBeat 是一个面向 Windows 的多轴脚本视频播放器。它读取 OpenFunScripter 导出的 funscript，把多轴动作实时转换成 TCode v0.3 指令，通过串口发送给 SR6、OSR2 一类设备，并同步播放对应视频。

名字取自图标上那只猫娘：*Neko*（猫）+ *Beat*（节拍）。

**当前版本：1.0.0**

![NekoBeat 主界面](screenshots/main-window.png)

## 功能

### 播放与同步

- 使用 libmpv 2 播放视频，界面基于 Qt Widgets，视频画面是 OpenGL 表面。
- 播放、暂停、停止、复位（回中）、跳转，并提供安全 / 标准 / 快速三档跳转安全设置与高级自定义。
- 播放与暂停可选缓动：恢复播放时设备按斜坡缓入脚本；暂停时若当前动作段即将结束，就滑行到该段终点再停（不超过 0.6 秒）。切换视频、断开设备、退出程序与急停始终立即停止。
- 在视频画面上单击右键可暂停或继续，双击画面或按 F11 进入全屏，Esc 退出全屏。
- 全屏时控制条自动隐藏，光标移到窗口底部即浮出；光标静止 3 秒后控制条与鼠标指针一并淡出。左右两侧面板改为光标贴到屏幕左、右边缘时浮出。
- 状态栏显示最近一个统计窗口内的最大相位滞后（`同步 ±N ms`），一眼就能看出是否有卡顿拖慢了设备。

### 媒体库

- 封面网格，带时长、轴数徽章、详情区、搜索、筛选与排序。
- 扫描在后台线程执行，不会卡住界面，也不影响正在进行的联动播放。
- 缩略图带缓存；文件被移动过可以从库里重新定位，清理缩略图缓存不会影响收藏数据。
- 收藏夹：右键卡片即可勾选所属的多个收藏夹，面板顶部可按收藏夹筛选，管理窗口支持新建、重命名、排序与清理失效项。

### 循环

![循环列表](screenshots/loop-list.png)

- 用 A/B 按钮标记区间，然后填写标题、标签、循环收藏夹与备注。
- 双击循环卡片即可循环播放该区间，到 B 点时通过安全斜坡平滑回跳到 A 点。
- 支持按收藏夹、标签、关键词筛选与排序，一个视频可以保存任意多段循环。

### 热力图

- 控制栏上方的色带兼作进度条，按动作点逐段绘制，绿 → 黄 → 橙 → 红 → 深红五档，0 % 与 100 % 贴上下边缘。
- 点击或拖动即可跳转。拖动期间只有画面跟着指针走，设备保持静止；松手时才缓动滑到松手位置并恢复联动。

### 轴控制

![轴限制面板](screenshots/axis-limits.png)

- **轴限制**（`设置 › 轴限制…`）：按比例缩放每轴行程，可保存多套配置档并导入导出。非播放状态下拖动限位滑块，或单击 0 % / 100 % 两端的圆点，设备会走到该限位位置，方便实际比对行程。
- **轴校准与测试**（`设置 › 轴校准与测试…`）：逐轴设置最小值、最大值、归位点、反向与脚本偏移（原始值 0–9999），并提供“测试 0 % / 100 % / 回到中位”三个真实驱动按钮。未连接设备也可以打开并保存数值，此时试位按钮禁用。
- 归位语义按轴区分：位置轴回到该轴配置的归位点，振动、润滑等振幅通道回 0（真正停止）。
- 连接设备后会先识别支持的轴（`D0/D1/D2`），识别完成前不发送任何动作命令，因此不会把设备没有的轴发给它。

### 设备链路

- 设备链路（串口、握手、动作定时器与 TCode 编码）运行在独立线程，界面卡顿不再拖慢设备指令。
- 支持 USB 串口与蓝牙串口（经典 SPP）；蓝牙口会标成 `蓝牙串口 · 设备名`，重试比 USB 更耐心。
- 逐条 TCode 命令日志默认关闭，可在 `设置 › 记录每条 TCode 命令（诊断）` 打开；环境变量 `NEKOBEAT_TCODE_LOG=1` 可覆盖。关闭时每 5 秒写一行联动统计。

### 界面

- 暗色极简风格：菜单栏 + 左侧封面网格媒体库 + 中间视频与控制条 + 右侧循环列表，左右两个面板可以互换位置。
- 界面语言默认英文，`设置 › 语言` 可在 English / 简体中文之间切换，选择会被记住，重启后生效。
- 列表分隔条拖动直接跟随指针，列数切换带迟滞，调整窗口大小时不会闪烁。

## 设备支持

| 连接方式 | 支持情况 | 说明 |
| --- | --- | --- |
| USB 串口（有线） | 支持 | 设备用 USB 连上，系统里出现 `USB-SERIAL CH340` 一类的串口后选中它连接即可。 |
| 蓝牙串口（经典 SPP） | 支持 | 设备固件需要把蓝牙做成串口透传（多数 ESP32 的 TCode 固件都是这种）。先在 Windows 里配对，再选标着 `蓝牙串口 · 设备名` 的端口。 |
| 纯 BLE（低功耗蓝牙） | 暂不支持 | 不生成串口的设备（如 Nordic UART）需要单独的原生蓝牙通道，当前版本尚未实现。 |
| WiFi / 网络 API（例如 Handy 的 WiFi 模式） | 暂不支持 | 需要按品牌单独编写适配层。 |

### 怎么判断自己的设备能不能用蓝牙

1. 先在 Windows“蓝牙和其他设备”里把设备配对好。
2. 打开 NekoBeat，点右上角 **连接 SR6**。列表里出现 **`蓝牙串口 · 设备名`** 的条目，就说明能用，选中它连接即可。
3. 如果只看到 `蓝牙串口（本机入站端口）`，或者配对之后一个串口都没有多出来，说明这台设备的蓝牙不是 SPP 串口类型，当前版本连不上，请改用 USB 线。

> 个别情况下配对后不会自动出现蓝牙串口，可以在 Windows“更多蓝牙设置 › COM 端口 › 添加 › 出站”手动添加一次。

连接成功后，状态行会写明当前走的是哪条链路，例如 `COM5 · 蓝牙 SR6-BT · SR6-Alpha5-ESP32 · TCode v0.3`；窗口较窄时把鼠标停在上面可以看完整内容。

## 系统与构建依赖

- Windows 10 / 11，64 位
- Qt 6.9.3（MinGW x64）
- MinGW 13.1
- CMake 3.24 或更新
- libmpv 2 开发包（由 `scripts\fetch_deps.ps1` 自动获取）
- 一台能通过串口接收 TCode v0.3 的设备（SR6、OSR2 一类）

## 从源码构建

```powershell
.\scripts\fetch_deps.ps1
.\scripts\build.ps1
```

`fetch_deps.ps1` 会把固定版本的 libmpv 下载到 `third_party\mpv` 并校验 SHA-256。`build.ps1` 配置并构建到 `build`，用 `ctest` 运行单元测试，把 `libmpv-2.dll` 复制到可执行文件旁，并用 `windeployqt` 收集 Qt 运行时。

生成目录固定为 `build`。MinGW Makefiles 无法处理非 ASCII 路径，所以当源码位于含中文的目录下时，脚本会临时把上级目录映射到一个空闲的 ASCII 盘符；源码位置本身不会改变。

如果你的 Qt 与 MinGW 不在 `C:\Qt`，两个脚本都接受 `-QtDir` / `-MinGwDir` 参数覆盖。

## 打包发布

便携包（包名中的版本号取自 `CMakeLists.txt`）：

```powershell
.\scripts\package_portable.ps1
```

源码包，直接从要发布的提交导出：

```powershell
git archive --format=zip -o dist\NekoBeat-1.0.0-Source.zip HEAD
```

源码包不含 `third_party/mpv`，从它构建的人需要先运行 `scripts\fetch_deps.ps1`。

## 数据存放位置

- `%APPDATA%\NekoBeat\` —— `favorites.json`、`loops.json`，以及 `library\` 下的媒体库缓存（`index.json` 和 `thumbs\`）。
- 轴限制配置档、校准数值与界面设置保存在注册表 `HKEY_CURRENT_USER\Software\NekoBeat\NekoBeat`。

程序不会向任何地方上传数据，也没有遥测。

## 安全提示

NekoBeat 会驱动真实硬件。请把急停放在手边，第一次运行新脚本时先把轴限制设得保守一些，确认没有问题再放开行程。
